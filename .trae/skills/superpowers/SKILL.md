# Superpowers

Superpowers 是一套完整的 AI 软件开发方法论和技能框架，为 AI 编程代理提供结构化的开发流程。

## 核心功能

1. **需求澄清** - 在编写代码前先询问用户真实需求，梳理完整规格说明
2. **设计规划** - 将复杂任务拆解为可读可理解的设计文档和实现计划
3. **测试驱动** - 强调 TDD（测试驱动开发）、YAGNI（不需要就不写）和 DRY（不要重复）原则
4. **子代理执行** - 启动子代理驱动的开发流程，自主完成任务、审查代码并持续推进
5. **质量控制** - 通过结构化技能确保 AI 遵循工程最佳实践

## 适用场景

- 需要构建新功能或完整项目时
- 需要系统化的开发流程而非简单代码生成
- 希望 AI 像资深工程师一样思考和执行任务
- 复杂任务的规划和分解
- 需要代码审查和质量保证

## 工作流程

### 1. 需求澄清阶段

在开始编码前，先与用户确认：
- 真正要解决的问题是什么？
- 期望的输出和验收标准是什么？
- 有哪些约束条件和边界情况？

### 2. 设计规划阶段

将需求转化为：
- 清晰的设计文档
- 分步骤的实现计划
- 测试用例和验收标准

### 3. 实现阶段

遵循以下原则：
- **TDD**: 先写测试，再写实现
- **YAGNI**: 只实现当前需要的功能
- **DRY**: 避免重复代码
- **小步快跑**: 每个改动都可测试、可回滚

### 4. 审查阶段

- 代码审查
- 测试覆盖率检查
- 性能和安全审查

## 子技能

Superpowers 包含多个可组合的子技能：

- **brainstorming** - 头脑风暴和创意发散
- **writing-plans** - 编写实现计划
- **subagent-driven-development** - 子代理驱动开发
- **systematic-debugging** - 系统化调试
- **requesting-code-review** - 请求代码审查
- **receiving-code-review** - 接收代码审查
- **using-git-worktrees** - 使用 Git Worktrees
- **writing-skills** - 编写技能文档

## 使用建议

1. **从需求开始** - 不要跳过需求澄清阶段
2. **先设计后实现** - 复杂任务必须先有设计文档
3. **测试先行** - 遵循 TDD 原则
4. **小步迭代** - 每个改动都要可测试
5. **持续审查** - 定期进行代码审查
