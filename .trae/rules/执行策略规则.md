# 执行策略规则

## 12. 分步执行策略（HIGH）
**规则**：
- 复杂任务拆分为多个小步骤
- 每步完成后询问用户是否继续
- 避免一次性生成大量代码
- 优先实现核心功能，再逐步完善

**执行流程**：
1. 分析任务复杂度
2. 如果涉及超过 3 个文件或需要大量代码，拆分任务
3. 每个步骤明确目标和范围
4. 完成一个步骤后确认再进行下一步

## 13. 增量修改原则（HIGH）
**规则**：
- 优先使用 Edit（修改）而非 Write（重写）
- 只修改必要的部分
- 保留现有代码结构和注释
- 最小化代码改动范围

**检查项**：
- [ ] 是否可以通过修改而非重写实现
- [ ] 是否保留了原有逻辑
- [ ] 是否破坏了现有测试
- [ ] 是否需要更新相关文档

## 14. 代码复用优先（HIGH）
**规则**：
- 优先使用项目中已有的工具函数
- 检查是否存在可复用的代码片段
- 避免重复造轮子
- 引用现有代码而非重写

**检查项**：
- [ ] 项目中是否已有类似功能
- [ ] 是否可以调用现有函数
- [ ] 是否需要提取公共模块
- [ ] 是否遵循 DRY 原则

## 15. Token 优化策略（MEDIUM）
**规则**：
- 代码块优先，文字解释精简
- 使用行内注释而非长篇文档字符串
- 避免重复说明已知的上下文
- 对于简单任务，直接给出代码

**优化技巧**：
- [ ] 减少冗余描述
- [ ] 使用代码注释代替文字解释
- [ ] 合并相似步骤
- [ ] 避免过度格式化
