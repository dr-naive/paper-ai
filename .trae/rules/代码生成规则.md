# 代码生成规则

## 7. 技术栈确认（CRITICAL）
**生成代码前必须确认**：
- 项目使用的编程语言（Python/Node.js/Go/Java/其他）
- 使用的框架和版本
- 现有的代码风格和规范
- 依赖管理工具（npm/pip/go mod/maven）

**询问模板**：
"为了确保代码适配，请确认以下信息：
1. 项目使用的编程语言是什么？
2. 使用的主要框架和版本？
3. 代码风格偏好（缩进、引号、分号等）？
4. 是否有现有的代码规范文档？"

## 8. 代码风格一致性（HIGH）
**规则**：
- 检测项目现有代码风格（缩进空格数、引号类型、分号使用等）
- 生成代码时严格遵循现有风格
- 引用项目中已有的相似实现作为参考
- 保持代码格式与项目一致

**检查项**：
- [ ] 缩进：空格/制表符，数量
- [ ] 引号：单引号/双引号/反引号
- [ ] 分号：结尾是否需要
- [ ] 换行：函数、类、控制语句的换行风格
- [ ] 命名：驼峰式/下划线式

## 9. 依赖预检（HIGH）
**规则**：
- 生成代码前检查是否需要新依赖
- 如果需要，列出依赖清单并等待用户确认
- 优先使用项目中已安装的包
- 提供替代方案（如果新依赖可能引起冲突）

**检查项**：
- [ ] 代码中是否使用了未在项目中出现的包
- [ ] 是否需要更新 requirements.txt/package.json
- [ ] 是否有兼容性问题
- [ ] 是否有更轻量的替代方案

## 10. 类型安全检查（HIGH）
**规则**：
- 对于强类型语言，必须添加类型注解
- 检查函数参数和返回值的类型一致性
- 确保类型转换的安全性
- 避免隐式类型转换

**检查项**：
- [ ] 函数参数是否有类型注解
- [ ] 返回值是否有类型声明
- [ ] 变量类型是否一致
- [ ] 是否存在潜在的类型错误

## 11. 命名规范检测（HIGH）
**规则**：
- 保持多文件之间的命名一致性
- 遵循项目现有的命名约定
- 使用有意义的变量和函数名
- 避免重复或冲突的命名

**检查项**：
- [ ] 变量/函数名是否清晰有意义
- [ ] 是否与项目现有命名风格一致
- [ ] 是否存在命名冲突
- [ ] 类名、函数名、变量名的命名规则是否统一
